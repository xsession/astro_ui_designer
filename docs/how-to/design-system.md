# How to build a reusable design system

1. Define semantic design tokens before proliferating raw values.
2. Create reusable component definitions for repeated structures.
3. Model variants as named property/value dimensions and keep instance overrides narrow.
4. Use Component Lab stories to document and verify important states.
5. Publish/import local design-library snapshots where projects need controlled sharing.
6. Keep code-component contracts explicit: props, slots, events, states and provided data.
7. Use find-usages before replacing a globally reused component, token, mixin, query or context.
